# 飞行棋网站：其他服务器部署指南

本指南对应 `sky-ludo-deploy-20261009.tar.gz` / `.zip` 部署包。网页、棋盘、联机、角色代码接管功能均在包内。房主可在“房间管理”查看所有入座玩家的接管码，并在对局开始前踢出其他玩家；观战者没有接管码。生产程序只使用 Node.js 内置模块，不需要数据库、Redis 或 `npm install`。

推荐路线：Ubuntu 22.04/24.04 → 安装网站 → 验证 HTTP → 配置域名 DNS → 启用 Nginx HTTPS → 双端验证。

## 1. 准备什么

| 项目 | 要求 |
|---|---|
| 服务器系统 | Ubuntu 22.04 或 24.04，使用 systemd；x86_64 或 ARM64/aarch64 |
| 登录权限 | root，或能使用 sudo 的用户 |
| 网络 | 能下载 Node.js 官方发行文件；HTTPS 安装时能访问 Ubuntu 软件源、GitHub 和证书签发服务 |
| 域名 | HTTPS 使用，例如 `game.example.com`；域名 A 记录指向新服务器公网 IPv4 |
| 端口 | 后端默认 TCP 8080；Nginx 使用 TCP 80/443 |
| 资源 | 可从 1 核、1 GB 内存起步；这只是部署起点，没有做该规格的并发容量验收 |

示例里的 `203.0.113.10`、`game.example.com`、`you@example.com` 和 SSH 密钥路径必须换成自己的值。不要把示例域名直接交给证书脚本。

本包适用于一台服务器运行一个游戏进程。游戏房间保存在该进程的内存中，不能直接使用多实例轮询或 PM2 cluster；玩家可能被分到没有对应房间的进程。

## 2. 部署包文件

解压后目录为：

```text
sky-ludo/
├── 部署说明.md                 本操作指南
├── FILES.sha256               包内文件校验清单
├── server.mjs                 HTTP/API/SSE 服务、房间与接管权限
├── engine.mjs                 飞行棋规则
├── board.mjs                  棋盘坐标与路径
├── package.json               启动/测试入口
├── public/                    必须整体保留
│   ├── index.html
│   ├── app.mjs
│   ├── board-view.mjs
│   ├── preview-board.mjs
│   ├── style.css
│   └── game.css
├── test/                      可选开发验证；网站运行不依赖这些文件
│   ├── engine.test.mjs
│   └── server.test.mjs
└── deploy/portable/
    ├── install.sh             首次安装、更新和失败回退
    ├── sky-ludo.service       专属 systemd 服务
    ├── setup-https.sh         域名、证书、Nginx 与续期配置

    └── nginx-https.conf.template
```

不能只上传 `public/`：这是有服务端房间状态的多人联机网站，必须启动 `server.mjs`。服务器证书由 HTTPS 脚本在新服务器上申请；SSH 登录密钥留在自己的电脑上。

## 3. Windows 上传部署包

打开 PowerShell，进入保存部署包的目录。例如：

```powershell
Set-Location "D:\downloads\sky-ludo"
$LudoServer = "root@203.0.113.10"
$LudoKeyFile = "D:\ssh\server.pem"
scp -i $LudoKeyFile .\sky-ludo-deploy-20261009.tar.gz "${LudoServer}:/tmp/sky-ludo-deploy.tar.gz"
ssh -i $LudoKeyFile $LudoServer
```

首次连接时核对服务器 SSH 指纹，再按提示接受。若使用密码登录，去掉 `-i $LudoKeyFile`。若使用非默认 SSH 端口，`scp` 用 `-P 端口`，`ssh` 用 `-p 端口`。

也可以用 WinSCP/SFTP 将 `.tar.gz` 上传到 `/tmp/sky-ludo-deploy.tar.gz`，再进入 SSH 终端。`.zip` 适合在 Windows 查看源码；服务器部署推荐用 `.tar.gz`。

## 4. 在服务器解压、安装依赖

以下命令在新服务器的 Ubuntu SSH 终端执行。如果当前不是 root，先执行：

```bash
sudo -i
```

安装基础工具：

```bash
apt-get update
apt-get install -y ca-certificates curl xz-utils tar coreutils iproute2 python3 util-linux openssl
```

解压并校验文件：

```bash
mkdir -p /opt/sky-ludo-package
tar -xzf /tmp/sky-ludo-deploy.tar.gz -C /opt/sky-ludo-package
cd /opt/sky-ludo-package/sky-ludo
sha256sum -c FILES.sha256
```

应全部输出 `OK`。若校验失败，重新上传或重新下载部署包，不要继续安装。

脚本已使用 Linux LF 换行。建议直接上传归档，不要经过可能自动转换换行的文本编辑器保存。

## 5. 首次安装网站

先检查端口：

```bash
ss -ltnp
```

8080 应空闲。然后执行：

```bash
bash deploy/portable/install.sh
```

安装脚本会：

1. 从 Node.js 官方站点下载固定版本，默认 `v22.23.3`，并校验官方 SHA256。
2. 创建专属 `sky-ludo` 系统用户。
3. 将网站安装到 `/opt/sky-ludo/current`，Node.js 放在 `/opt/sky-ludo/runtime`。
4. 创建 `/etc/sky-ludo/sky-ludo.env` 和 `sky-ludo.service`。
5. 启动服务并检查本机 `/health`。

首次配置是：

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=8080
TRUST_LOOPBACK_PROXY=0
```

验证：

```bash
systemctl status sky-ludo --no-pager
curl -fsS http://127.0.0.1:8080/health
```

正常返回类似 `{"ok":true,"rooms":0}`；`rooms` 是当前房间数，有人创建房间后可以大于 0。

如需先通过 IP 试玩，在服务器提供商的安全组/网络防火墙中允许 TCP 8080，浏览器打开：

```text
http://203.0.113.10:8080/
```

8080 是 HTTP 端口，不能用 `https://203.0.113.10:8080/`。后面启用 HTTPS 后，推荐统一使用域名入口。

如果只需要 IP + HTTP，可以停在此步骤。角色代码的复制功能在 HTTP 下可能使用浏览器的兼容处理；推荐 HTTPS 作为正式入口。

需要改 Node.js 版本时，指定实际已经发布的完整 v22/v24 版本，而不是 `v24.x.y`：

```bash
NODE_VERSION=v22.23.3 bash deploy/portable/install.sh
```

## 6. 配置域名 DNS 和网络端口

以 `game.example.com` 为例，在域名管理平台添加：

| 类型 | 主机名 | 值 |
|---|---|---|
| A | `game` | 新服务器公网 IPv4，例如 `203.0.113.10` |

若使用根域名 `example.com`，主机名通常填写 `@`。域名必须解析到本次部署的服务器。没有部署 IPv6 时不要添加 AAAA 记录；已存在错误 AAAA 记录也会影响访问或证书验证。

在云安全组中开放 TCP 80/443。证书使用 HTTP-01 验证，所以即使最终只用 HTTPS，也需要让签发服务能访问 80；后续续期仍需要这一入口。

如果 UFW 已启用，可执行：

```bash
ufw status
ufw allow 80/tcp
ufw allow 443/tcp
```

脚本不会自动启用 UFW，也不会关闭已有防火墙。SSH 放行规则应按你实际使用的 SSH 端口保留。

验证解析，例如：

```bash
getent ahostsv4 game.example.com
```

应能看到新服务器 IPv4。DNS 刚改完时不同解析器可能仍有旧缓存，可稍后重试。首次证书签发建议先使用普通 DNS 解析，避免 CDN/代理拦截验证路径。

## 7. 启用域名 HTTPS

先结束试玩房间，确认 `/health` 中 `rooms` 为 0；HTTPS 切换会重启游戏。

```bash
curl -fsS http://127.0.0.1:8080/health
ss -ltnp
```

80/443 若被 3x-ui、Apache、Caddy 或其他服务占用，先看第 12 节，不要强行停止这些服务。

使用自己的域名和邮箱执行：

```bash
cd /opt/sky-ludo-package/sky-ludo
bash deploy/portable/setup-https.sh --domain game.example.com --email you@example.com
```

该脚本会准备 Nginx、为本域名单独申请证书、设置续期，配置 HTTP → HTTPS 跳转，并将游戏后端调整为本机监听、启用可信本机代理 IP。具体路径和维护命令以脚本成功输出为准。

如果确实接受结束所有当前房间，可显式使用：

```bash
bash deploy/portable/setup-https.sh --domain game.example.com --email you@example.com --confirm-end-rooms
```

游戏应通过下列链路访问：

| 入口 | 用途 |
|---|---|
| `http://game.example.com/` | 跳转到 HTTPS，另保留证书验证路径 |
| `https://game.example.com/` | 创建/加入房间、棋盘、联机 API 与 SSE |
| `http://127.0.0.1:8080/` | Nginx 访问 Node.js 后端，本机维护使用 |

HTTPS 后游戏配置中的 `HOST` 应为 `127.0.0.1`，`TRUST_LOOPBACK_PROXY` 应为 `1`。浏览器地址不需要加 `:8080`。仅设置 DNS A 记录并不会自动启用 HTTPS。

HTTPS 初始化要求原游戏后端监听 `0.0.0.0` 或 `127.0.0.1`；默认安装已符合。公网 IPv6 可以由 Nginx 接收、再转发到 IPv4 回环后端。如果手动将游戏 `HOST` 改成了 `::` / `::1`，请先在没有房间时改回 IPv4 监听并重启，再执行本脚本。

如果原先开放过公网 8080，可在云安全组中关闭这个临时规则。后端绑定回环地址后，外部本来就不能直接连接它；不需要关闭其他应用的端口。

## 8. 验证部署结果

服务器检查：

```bash
systemctl is-active sky-ludo nginx
nginx -t
curl -fsS http://127.0.0.1:8080/health
curl -I http://game.example.com/
curl -I https://game.example.com/
```

HTTP 应返回跳转，HTTPS 首页应返回 200，证书域名应匹配且未过期。

再用两个独立浏览器或电脑和手机验证：

1. 打开 HTTPS 首页，输入昵称，点击“创建房间”。
2. 第一端选择 2 人，复制邀请链接。
3. 第二端通过邀请链接加入，两端都显示“实时联机”。
4. 房主开始，当前玩家掷骰；两端点数和回合一致。
5. 移动一架飞机，确认另一端同步；保持连接至少一分钟，确认连接没有反复断开。
6. 如需检验角色交接，让第三个观战端输入角色代码，验证原玩家转为观战、棋局继续。
7. 验证结束后，房主结束游戏，两端退出自建房间。

服务器单元测试可选执行：

```bash
cd /opt/sky-ludo-package/sky-ludo
/opt/sky-ludo/runtime/bin/node --test test/engine.test.mjs test/server.test.mjs
```

这些测试创建独立的本机测试服务，不会连接当前线上房间。测试中的示例 Host/Origin 是测试夹具，不是网站域名配置。单元测试通过不能替代上面的真实浏览器验证。

## 9. 后续更新网站

将新版部署包上传为另一个文件，例如 `/tmp/sky-ludo-new.tar.gz`，解压到另一个目录，保留旧包：

```bash
mkdir -p /opt/sky-ludo-package-new
tar -xzf /tmp/sky-ludo-new.tar.gz -C /opt/sky-ludo-package-new
cd /opt/sky-ludo-package-new/sky-ludo
sha256sum -c FILES.sha256
curl -fsS http://127.0.0.1:8080/health
bash deploy/portable/install.sh --update
```

更新保留服务器现有环境配置，并在 `/opt/sky-ludo/backups/` 下保存文件备份。安装脚本会检查房间；存在房间时默认拒绝更新。接受结束房间时才使用：

```bash
bash deploy/portable/install.sh --update --confirm-end-rooms
```

更新会短暂停服，健康检查失败时脚本尝试恢复原文件和服务。文件回退不能恢复进程内的房间，因此操作前要让玩家退出，并在切换期间停止创建新房间。

新服务器用了本指南的安装脚本后才能直接使用其 `--update`。若已有其他方式安装的同名 `sky-ludo` 服务，脚本会要求先人工确认和迁移，避免覆盖不相关部署。

只更新游戏源码时不需要重复签发证书或重跑 HTTPS 初始化。若只改 Nginx 配置：

```bash
nginx -t
systemctl reload nginx
```

## 10. 日常管理

```bash
systemctl status sky-ludo --no-pager
journalctl -u sky-ludo -n 100 --no-pager
systemctl restart sky-ludo
systemctl stop sky-ludo
systemctl start sky-ludo
```

`restart` 和系统重启会结束全部内存房间。角色代码用于同一存活房间内换设备或换人，不能在进程重启后恢复棋局。

证书自动续期使用 `sky-ludo-acme-renew.timer`，可以查看任务及续期日志：

```bash
systemctl status sky-ludo-acme-renew.timer --no-pager
systemctl list-timers --all --no-pager
journalctl -u sky-ludo-acme-renew.service -n 100 --no-pager
```

证书续期成功后重载 Nginx；正常重载不需要重启游戏。

要变更后端端口，可编辑 `/etc/sky-ludo/sky-ludo.env` 的 `PORT`，同时调整 Nginx 的 `proxy_pass`。两处必须一致；游戏重启的房间影响同上。

## 11. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 首页 404 或出现别的网站 | 域名是否指向正确 IP；80/443 由谁监听；Nginx 的 server_name 是否是自己的域名；是否仍进入了订阅服务或旧站点 |
| 502 Bad Gateway | `systemctl status sky-ludo`；本机 `/health`；Nginx 后端端口；游戏后端使用 `http://127.0.0.1:8080` |
| ERR_SSL_PROTOCOL_ERROR | 不要对 HTTP 8080 使用 HTTPS；HTTPS 应进入配置了证书的 Nginx 443 |
| 证书申请失败 | A/AAAA 解析、云安全组 TCP 80、操作系统防火墙、CDN 是否拦截 `.well-known/acme-challenge/` |
| 建房/走棋返回 403 | 反代必须保留原始 Host，如 `proxy_set_header Host $http_host;`；不要通过放开跨站限制掩盖代理配置问题 |
| 经代理的所有人频繁返回 429 | 后端应启用 `TRUST_LOOPBACK_PROXY=1`，只监听本机；代理覆盖单值 X-Real-IP 为真实连接 IP |
| 多人画面不同步/反复断线 | SSE 需要 `proxy_buffering off`、`proxy_cache off`、合适的读取超时；CDN 也不能缓存 `/api/` 或缓冲事件流 |
| 更新/重启后原房间不存在 | 这是当前内存房间实现的行为；源码备份不等于房间备份 |
| “不是本脚本创建的部署” | 当前服务来自其他安装方式；不要强行覆盖，先备份并核对服务路径/用户/配置 |
| 脚本出现 `$'\r'` 或 `/bin/bash^M` | 文件被改成 CRLF；重新上传原始归档并解压 |

房间凭证存在 SSE 请求 URL 中，Nginx 模板关闭游戏入口访问日志。不要为了排错公开完整请求 URL、接管代码或 API 响应；先查看状态码和本机健康结果。

### HTTPS 首次配置失败后如何重试

先修复失败原因，例如 DNS 未生效、80 未放行、GitHub 下载失败或有玩家新建了房间。脚本会尝试恢复原游戏环境，并可能保留本次建立的 HTTP 站点；查看终端最后的恢复结果。

仅在 HTTPS 初始化失败、尚未成功上线时，按脚本打印的路径检查并移除本次站点。例如域名是 `game.example.com`：

```bash
ls -l /etc/nginx/sites-available/sky-ludo-game.example.com.conf
ls -l /etc/nginx/sites-enabled/sky-ludo-game.example.com.conf
```

确认这两个文件是本次失败操作建立的站点，而不是自己原有的站点后执行：

```bash
rm -f -- /etc/nginx/sites-enabled/sky-ludo-game.example.com.conf /etc/nginx/sites-available/sky-ludo-game.example.com.conf
nginx -t
systemctl reload nginx
cd /opt/sky-ludo-package/sky-ludo
bash deploy/portable/setup-https.sh --domain game.example.com --email you@example.com
```

保留 `/etc/sky-ludo/acme`、`/opt/sky-ludo/acme-runtime` 和本次证书目录；带有本脚本版本/域名拥有者标记的证书目录可在重试时复用。脚本仍会拒绝未知拥有者的现有目录。如果 HTTPS 已经成功配置，不要删除站点；原命令可以检查当前配置和证书，日常续期由 timer 完成。

## 12. 已有 Nginx / 宝塔 / 3x-ui / 其他 HTTPS 服务

独立空闲服务器可以直接使用上面的 HTTPS 脚本。已有反向代理的服务器，应复用它的 443 入口，按域名添加站点，不要让两个程序争用同一个监听地址和端口。

如果使用宝塔或其他面板：

1. 先用安装脚本启动 Node.js 后端。
2. 在面板中为自己的游戏域名创建反向代理站点，后端填 `http://127.0.0.1:8080`。
3. 申请该域名证书，启用 HTTPS。
4. 保留 Host、覆盖 X-Real-IP，并关闭 SSE 缓冲/缓存；可参照包内 Nginx HTTPS 模板。
5. 在游戏环境配置中设置 `HOST=127.0.0.1` 和 `TRUST_LOOPBACK_PROXY=1`，在没有房间时重启游戏。
6. 再进行双端验证。

如果 443 由 3x-ui 订阅服务占用，需要另外制定迁移步骤：备份其配置、将订阅端口改到内部端口，再由统一 Nginx 按域名/原订阅路径转发。面板入口路径和已有订阅 URL 都要考虑兼容。此部署包不会自动迁移其他软件。

Nginx 反代其他已启用 TLS 的服务时，上游应使用 `https://`，正确设置 `proxy_ssl_name`、系统 CA 和合适的 `proxy_ssl_verify_depth`，保留证书校验。游戏 Node.js 后端是 HTTP，不能照搬这组上游 TLS 配置。

## 13. 验证范围与后续建议

包内网站来自本次已验证的游戏源码：规则/角色交接已有测试证据，HTTPS 双端创建、加入、开始、掷骰、SSE 心跳和同步在现有服务器通过。本包使用可移植模板，不携带旧服务器专用迁移脚本。

安装和 HTTPS 辅助脚本会做语法、参数和打包校验；新的 Ubuntu 服务器上实际安装、systemd 启动、证书签发和更新回退仍需按本指南验证，不能把本地检查当作新服务器上线证明。

迁移已有正式域名时，建议先用临时子域名完成新服务器的 HTTPS 双端验证，再迁移正式域名并为其配置证书。HTTP-01 签发要求对应域名已指向新服务器；变更域名时按第 12 节人工审查代理配置，初始化脚本不会自动覆盖已有域名站点。需要重启后继续棋局或跨实例扩容时，再增加持久化与房间恢复。
